# Research engine

`ResearchProvider` is the boundary for official APIs, approved search providers, feeds, or compliant retrieval. The core does not scrape a marketplace directly. Wikimedia Commons and Wikipedia use public APIs for source-backed evidence. Open Food Facts can be selected with `RESEARCH_PROVIDER=openfoodfacts`; its read-only legacy text-search endpoint requires a descriptive `OPENFOODFACTS_USER_AGENT`, is limited to the food catalog, and may return images and source URLs but generally does not provide marketplace prices. The development provider remains available with `RESEARCH_PROVIDER=development` for deterministic tests.

Provider results are labelled `text_search`. When returned candidate images are compared with an uploaded image, the application labels that separate step `image_similarity_ranking`; its current implementation is Sharp RGB pixel similarity, not semantic product recognition or reverse-image search.

Credential-dependent providers are not silently replaced by the empty development provider. For example, `RESEARCH_PROVIDER=ebay` without both eBay credentials is reported as `unavailable`; a mixed configuration such as `openfoodfacts,ebay` can still return results from Open Food Facts while logging the eBay configuration failure. The health endpoint exposes each configured provider's `configured` or `unavailable` status.

`RESEARCH_PROVIDER=printful` enables the official Printful catalog read API without credentials. It is a print-on-demand supplier catalog, not a general marketplace: results provide catalog titles, models, brands, images, IDs, variants, and currency when supplied, but the list endpoint does not guarantee a price or consumer listing URL. Its results are text-matched only; it does not perform image search. Candidate image comparison, when available, is a separate local pixel-similarity ranking step.

The API health response exposes the same capability contract for every configured source: configured/availability status, supported search modes, coverage, fields actually returned, credentials, restrictions, source attribution, and the time the metadata was checked. The orchestrator records per-provider success, empty, failed, and not-configured states. A mixed result is returned as `partial_success`; an all-successful empty run is `no_matches`. These states are not interchangeable with provider outage or missing credentials.

Research queries are generated only from persisted clues (brand, model, product type, visible text, and distinctive characteristics). The provider boundary remains text-based unless a provider explicitly implements image search. Uploaded images are used after discovery for the separate local RGB pixel-similarity ranking step; no provider is described as doing reverse-image or semantic image search.

The create flow also accepts an optional public product URL. The API validates only HTTP(S) URLs, rejects credentials and local/private/internal hosts, resolves DNS before fetching, follows at most two validated redirects, applies an eight-second timeout and a one-megabyte response limit, and parses public metadata without executing page scripts or treating page content as instructions. Blocked, unsupported, malformed, or unavailable pages return a restricted import status; the implementation does not bypass access controls.

Shopify remains an optional connected commerce account using the existing server-side OAuth boundary. It is scoped to the selected workspace and is unrelated to competitor marketplace discovery; public research sources remain usable without connecting Shopify.
